# FilaShift operations runbook

Owner: David Jackson, Jackson Technology Solutions LLC (a subsidiary of Jackson Consolidated Group of Companies LLC). Contact/alert email: support@jacksoncgc.com.

## What it is
FilaShift (https://filashift.com) converts Bambu Studio / OrcaSlicer 3MF projects between printers (Bambu, Flashforge AD5X/Creator 5, Snapmaker U1, Prusa, Creality, Elegoo, Qidi, Voron, etc., 226 profiles) entirely in the visitor's browser. Static Vite + React + Tailwind site. No backend, no database, no uploads. Licence AGPL-3.0-or-later (printer profiles derive from OrcaSlicer).

## Validation before any engine/profile release
- `scripts/matrix.ts` converts test sources to many targets; `scripts/slice-matrix.sh` slices outputs with the OrcaSlicer and Bambu Studio CLIs (AppImages, run headless; set EXTRA=--allow-mix-temp). Previous baseline: 154/154 slice OK.
- `scripts/roundtrip.ts` checks A->B->A keeps geometry and paint/colour data identical.
- Spot-check in a real browser: upload a 3MF, convert, download, no console errors, and confirm no POST/upload requests leave the page.
- Test corpus (15 real/synthetic 3MFs incl. 5 MakerWorld models, plus baseline results) lives on the Droplet at `/srv/filashift-testdata` (private, not web-served). Copy it to your workspace with scp.
- Slicer CLIs: download the latest OrcaSlicer and Bambu Studio Linux AppImages from their GitHub releases, `--appimage-extract`, and run headless via xvfb-run with `--datadir` (see `bambu-wrapper.sh` / `orca-wrapper.sh` in the test corpus; OrcaSlicer may need extra GTK/webkit libs extracted from Ubuntu .debs).
- Never claim a printer is compatible unless its converted output slices in the destination slicer.

`./deploy/release.sh` (typecheck, build, upload, atomic swap, smoke test). `./deploy/release.sh --rollback` restores the previous release instantly. After a release, push the commit to the Droplet git repo.

## Routine health check
1. `curl -sI https://filashift.com` 200, `https://www.filashift.com` 301, `http://filashift.com` 308; profiles/index.json and fonts/fonts.css 200.
2. Cert expiry for both names (`openssl s_client`), should be >20 days out.
3. On server: `systemctl is-active caddy`, `journalctl -u caddy --since -24h | grep -i error`, `df -h /`, `free -m`, `uptime`, pending `apt list --upgradable`, reboot-required flag.
4. DigitalOcean API (credential handle for api.digitalocean.com in the vault): droplet status, backups present, firewall status, alert policies.
5. Caddy updates: `apt update && apt install caddy` then `caddy validate --config /etc/caddy/Caddyfile` and reload.
6. Filament prices: `systemctl status filashift-filament.service` succeeded within 6h; `https://filashift.com/data/filament.json` `updated` is < 8h old and `count` is in the hundreds (about 900 in Nov 2026).

## Filament price finder (filashift.com/filament)
- Page: `client/src/pages/filament.tsx` (route `/filament`; filashift.com uses real paths, other hosts use `#/` routing, see `client/src/routing.ts`). Shared header/footer in `client/src/components/site-chrome.tsx`.
- Collector: `scripts/collect_filament.py` (Python stdlib only), installed at `/opt/filashift/collect_filament.py`. Reads each brand store's public Shopify `products.json` and writes `/var/www/filashift-data/filament.json`. It refuses to overwrite the file when fewer than 50 offers parse, so a bad run leaves the last good data in place.
- Schedule: `deploy/filashift-filament.service` + `.timer` in `/etc/systemd/system/`, runs at 00/06/12/18:15 UTC (+ up to 10 min random) as user caddy. Manual run: `systemctl start filashift-filament.service`; logs: `journalctl -u filashift-filament`.
- Serving: Caddy maps `/data/*` to `/var/www/filashift-data` (5 min cache). This folder is outside the web root so releases never wipe it. After a code change to the collector, reinstall it: `install -m 755 scripts/collect_filament.py /opt/filashift/`.
- `/var/www/filashift-data/config.json` = `{"amazonTag":"filashift-20"}` (David's Amazon Associates store ID, set Nov 23 2026). It turns on the tagged Amazon search box and the Associates disclosure; no release needed. Amazon product prices need the Creators API, available after 10 qualifying sales in 30 days.
- Stores (edit `STORES` in the script): us.polymaker.com, us.elegoo.com, eryone3d.com, www.overture3d.com, atomicfilament.com, www.inslogic3d.com, www.jayo3d.com, www.amolen.com, www.protopasta.com, kingroon.com, www.printedsolid.com (reseller, brand = vendor), store.sunlu.com, siraya.tech, www.sovol3d.com, qidi3d.com, us.anycubic3d.com, www.flashforge.com, us.snapmaker.com, www.3dfuel.com (added Nov 23 2026; not reachable: esun3dstore.com 403, Bambu US and Creality stores, MatterHackers). Test locally with `python3 scripts/collect_filament.py /tmp/out.json --cache /tmp/fil` and check counts per store before deploying a parser change.
- Affiliate links: add an `affiliates` map to config.json keyed by store host; no release needed. Two forms:
  - `{"store.sunlu.com": {"params": {"sca_ref": "12345.abcd"}}}` appends query parameters (UpPromote, Shopify `ref`, etc.).
  - `{"us.elegoo.com": {"template": "https://elegoo.sjv.io/c/XXX/YYY/ZZZ?u={url}"}}` wraps the product URL for networks such as Impact or Awin (`{url}` is URL-encoded).
  Links that get an affiliate are marked `rel="sponsored"` and the disclosure appears on the prices page and in the converter's "Filament for this print" panel. Keep `amazonTag` alongside. Validate JSON with `python3 -m json.tool` before saving.
- "Filament for this print" (converter result): per used slot, the two cheapest in-stock 1.75 mm single spools (0.5–1.25 kg) whose colour is close to the project colour, one per store, plus links to `/filament?f=FAMILY&q=COLOUR` and a tagged Amazon search.
- Stores must be public filament retailers' own listings; only add a store if its product feed is publicly available and terms allow linking. No product images are shown, so visitors make no third-party requests.

## Problem reports (/api)

- Service: `filashift-api.service` runs `/opt/filashift/filashift-api.py` (stdlib Python, user caddy) on 127.0.0.1:8787; Caddy proxies `/api/*` with a 16 KB body cap. Source: `deploy/filashift-api.py`, unit `deploy/filashift-api.service`.
- Endpoints: `POST /api/report` (message, link, email, details, page; honeypot field `website`), `GET /api/health`. Limits: 5 reports per IP per hour, 200 per day overall. No request logging.
- Reports land in `/var/lib/filashift/reports/<id>.json` with `"status": "new"`. There is no outgoing email: the Ops Teammate checks daily (`ls /var/lib/filashift/reports`), triages, sets `status` to `seen`/`fixed`, and tells David about anything needing a reply (reply from support@jacksoncgc.com). Delete reports older than 12 months (privacy page promise): `find /var/lib/filashift/reports -name '*.json' -mtime +365 -delete`.
- The 3MF file is never sent; "conversion details" (file name, source/target, counts, warnings, browser) are included only if the visitor leaves the box ticked.
- Pages: /about, /privacy, /terms, /contact (client/src/pages/info.tsx). Privacy page states no analytics, no cookies, no access logs — keep Caddy without a `log` directive, and update the page if that ever changes.
