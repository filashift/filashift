# FilaShift operations runbook

Owner: David Jackson, Jackson Technology Solutions LLC (a subsidiary of Jackson Consolidated Group of Companies LLC). Contact/alert email: support@jacksoncgc.com.

## What it is
FilaShift (https://filashift.com) converts Bambu Studio / OrcaSlicer 3MF projects between printers (Bambu, Flashforge AD5X/Creator 5, Snapmaker U1, Prusa, Creality, Elegoo, Qidi, Voron, etc., 226 profiles) entirely in the visitor's browser. Static Vite + React + Tailwind site. No backend, no database, no uploads. Licence AGPL-3.0-or-later (printer profiles derive from OrcaSlicer).

## Code

For partial results, keep the original sample and the alternative layout or material control separate. A native slicer failure is not a pass even if a partial G-code file exists; do not replace its exit code with a bed warning. `scripts/test-slice-classification.sh` checks the harness during releases. The November 25 partial retests are summarized in `docs/partial-slice-retests-2026-11-25.md`.

For filament conflicts, identify the flagged project slot without presuming the spool label is wrong. `scripts/check-filament-review-ui.mjs` checks that the mixed-material sample offers both paths (incorrect preset versus intentional mix), and that the all-PLA control shows no action. Preset corrections are never applied automatically or counted as a pass for the mixed original.

The base ZR's PLA qualification is separate from its 2/3 catalog result. `scripts/check-zr-pla-label.mjs` checks the label and mixed-project note in all four languages, and the generic partial-result fallback when the slicer version no longer matches the evidence.

## Validation before any engine/profile release
- `scripts/matrix.ts` converts test sources to many targets; `scripts/slice-matrix.sh` slices outputs with the destination CLIs. For certification use stock safety checks (`unset EXTRA`); historical diagnostic runs with overrides are not stock passes.
- `scripts/roundtrip.ts` checks A->B->A keeps geometry and paint/colour data identical.
- Spot-check in a real browser: upload a 3MF, convert, download, no console errors, and confirm no POST/upload requests leave the page.
- Test corpus (15 real/synthetic 3MFs incl. 5 MakerWorld models, plus baseline results) lives on the Droplet at `/srv/filashift-testdata` (private, not web-served). Copy it to your workspace with scp.
- Slicer CLIs: download the latest OrcaSlicer and Bambu Studio Linux AppImages from their GitHub releases, `--appimage-extract`, and run headless via xvfb-run with `--datadir` (see `bambu-wrapper.sh` / `orca-wrapper.sh` in the test corpus; OrcaSlicer may need extra GTK/webkit libs extracted from Ubuntu .debs).
- Never claim a printer is compatible unless its converted output slices in the destination slicer.

### Fork slicers as sources (Creality Print, ElegooSlicer, Anycubic Slicer Next)
- The engine names the real source slicer even when a fork writes a Bambu/Orca Application tag (`detectFork` in `client/src/engine/engine.ts`): Anycubic Slicer Next writes `BambuStudio-<its version>` plus `X-ACNext-Client-*` in slice_info.config and `app_full_name` in the settings; Creality Print writes `Creality_Print V…`, `X-CX-Client-*` and `Metadata/creality.config`; ElegooSlicer writes `ElegooSlicer-…`. Converted files get a clean Bambu/Orca slice_info header and drop creality.config, so the output no longer claims to be from the fork.
- Fork-only settings (Anycubic ACE `ace_t_*` slot vectors and `_HS/_BRASS` temperature/fan variants, Elegoo `support_mms`, Creality `multicolor_method`, CFS flush keys, etc.) are not copied; plain keys already hold the active values (checked with a Kobra S1 Max hardened-steel project). Creality-only plates (Epoxy Resin, Customized) fall back to the target's plate with a warning. Creality Print 7 mixed filaments (`mixed_filament_definitions`) get an analysis note; parts on a blend print with slot 1.
- Fixtures in the test corpus (`~/td/`): `elegooslicer_cc2.3mf` and `anycubic_kobra3.3mf` are real CLI exports made by `scripts/make_fork_fixtures.sh FORKDIR OUTDIR` (ElegooSlicer 1.5.3.5 AppImage from GitHub; Anycubic Slicer Next 2.0.0.6 official .deb from cdn-universe-slicer.anycubic.com, `dpkg-deb -x`; presets flattened by `scripts/fork_presets.py`). `crealityprint_k2plus.3mf`, `crealityprint_k1c_cfs.3mf` (Epoxy Resin Plate) and `crealityprint7_mixed.3mf` are SYNTHETIC, written by `scripts/make_creality_fixture.py PROFILES_DIR OUT MACHINE PROCESS FILAMENT [BED] [--mixed]` from Creality Print 6.3.1's own system presets and its bbs_3mf.cpp layout, because the Creality Print 6.3.1 Linux CLI segfaults on export/slice and 7.3.2's CLI has no `--export-3mf`.
- Test: `npx tsx scripts/matrix.ts /tmp/fm ~/td/crealityprint_k2plus.3mf:cpk2 ~/td/elegooslicer_cc2.3mf:el ~/td/anycubic_kobra3.3mf:ac -- bambu-lab-x1-carbon bambu-lab-h2d snapmaker-u1 flashforge-ad5x creality-k2-plus elegoo-centauri-carbon-2 anycubic-kobra-3`, slice with `slice-matrix.sh`, and round-trip with `scripts/roundtrip.ts ~/td/anycubic_kobra3.3mf /tmp/rt bambu-lab-x1-carbon anycubic-kobra-3` (paint must stay identical). Baseline Nov 24 2026: 50/50 fork outputs slice rc=0, 5/5 six-step round trips paint-identical.
- Cross-check in the forks' own CLIs: FilaShift's `elegoo-centauri-carbon-2` output slices in ElegooSlicer 1.5.3.5 (needs `--allow-newer-file`; the GUI asks instead). Anycubic `bed_exclude_area` (fixed Nov 24 2026): OrcaSlicer's Kobra 3 profiles write it as one border frame (`0x0,255x0,…,2x2,2x253,…`), which Anycubic Slicer Next reads as one box per 4 points, i.e. a filled bed, and rejected every project ("too close to exclusion area", rc=-64). `frame_to_strips` in `scripts/build_profiles.py` rewrites such frames for Anycubic printers as 4 chained 2 mm border strips (16 points, same layout as Anycubic's own Kobra 3 profile and Orca's Kobra 3 Max). Only the `anycubic-kobra-3*` profiles change; Kobra 3 Max already uses strips and Kobra 3 V2 / S1 / S1 Max have none.
- Test: convert `x1c_paint ad5x_project prusa_synth` plus the five fork fixtures to `anycubic-kobra-3 anycubic-kobra-3-n02 anycubic-kobra-3-n06 anycubic-kobra-3-n08` with `matrix.ts`, slice with `slice-matrix.sh` (OrcaSlicer) and `~/slicers/forks/run-ac` (Anycubic Slicer Next). Baseline: Orca 32/32 rc=0; Anycubic 28/32, the 4 failures are x1c_paint (PLA+PETG) hitting Anycubic's mixed-temperature check, which its CLI cannot bypass (no `--allow-mix-temp`); a PLA-only copy slices 4/4.
- Limitation: with strip encoding OrcaSlicer 2.5.2 no longer rejects objects placed inside the 2 mm border (same as its own Kobra 3 Max profile); Anycubic Slicer Next still does. No encoding found that enforces the border in both (frame, strips, CCW strips, Anycubic's value and a 32-point slit ring tested).

## Release / rollback
`./deploy/release.sh` (typecheck, build, prerender, Spanish mobile single-spool gate, upload, atomic swap, smoke test). The pre-upload gate runs `npm run test:release:mobile-es` against the built candidate; a failure stops the release. `scripts/prerender.mjs` (playwright-core + local Chrome; set `CHROME=` if it isn't found) renders every public route to `dist/public/<route>/index.html` plus `404.html`, `sitemap.xml` and `robots.txt`. Add new routes to its `ROUTES` list (guides are picked up from `client/src/lib/guides.ts` automatically). Caddy serves `{path}/index.html` for pages and `404.html` with status 404 for anything else. `./deploy/release.sh --rollback` restores the previous release instantly. After a release, push the commit to both remotes: the Droplet git repo and the public GitHub mirror (scan the diff for secrets and data first).

## Localized URLs and hreflang
- Every public, indexable page exists in four languages: English unprefixed (`/guides/3mf-to-stl`) and `/es/…`, `/de/…`, `/fr/…` (`/de/guides/3mf-to-stl`; home pages are `/es/`, `/de/`, `/fr/` with the slash, Caddy 301s `/de` to `/de/`). Localized routes: home, `/guides` and every guide, `/tested`, `/filament`, `/about`, `/faq`, `/creators`, `/privacy`, `/terms`, `/contact` (`isLocalizedRoute` in `client/src/lib/i18n.tsx`, `NOT_LOCALIZED` in `scripts/prerender.mjs`). `/source` and `/api` stay English-only, without hreflang (`/source` keeps its single English sitemap entry). The 404 page has a translated copy per language (`404.html`, `es/404.html`, `de/404.html`, `fr/404.html`): robots noindex, no canonical, no hreflang, not in the sitemap, buttons to that language's home and guides.
- The path decides the language and beats `?lang=` and the saved choice; a path visit is not saved. Unprefixed URLs keep the old rules (`?lang=`, then `filashift-lang` in localStorage, then the browser's first language). wouter runs with `base="/de"` etc. (`LOCALE_BASE`), so every internal `<Link>` keeps the prefix; use `~/source` for a link that must leave it. The header language menu (`setLang` → `langSwitchUrl`) goes to the same page in the other language and saves the choice; non-localized pages switch with `?lang=`.
- `scripts/prerender.mjs` renders each localized route four times (86 files) and fails if a localized page lacks its self canonical or the hreflang set, or if its title or description is still English. The HTML is already translated (`<html lang>`, title, description, og:title/description, `og:locale` + `og:locale:alternate`, JSON-LD incl. the site-wide `#ld-app` block); `usePageMeta` in `client/src/lib/seo.ts` writes the canonical and `<link rel="alternate" hreflang>` for en, es, de, fr and x-default (English). New page titles, descriptions and JSON-LD text need entries in es/de/fr.json.
- `sitemap.xml` lists every language URL with `xhtml:link` alternates (and the same `lastmod` for every language of a guide).
- Caddy only adds redirects (`/es` → `/es/` keeping the query, and `/es/filament/` → `/es/filament` like the English one; same for de/fr). `/<lang>/<route>` is served from `/<lang>/<route>/index.html` by the existing page rule, unknown `/es/…`, `/de/…` and `/fr/…` paths (`/de/source`, `/de/nope`) get that language's `<lang>/404.html`, any other unknown path (`/it/`, `/nope`) the English `404.html`, always with status 404, and the CSP is the same.
- Test: `npm run build && node scripts/prerender.mjs && node scripts/check-seo-locales.mjs` (vite preview with the Caddyfile's page and 404 rules; `BASE=https://filashift.com` for production; `SHOTS=dir` saves de/fr screenshots). It checks raw HTML (no JavaScript) of every localized route in all four languages, the sitemap, 390 px overflow, the language menu and prefixed links.

## Filament price finder (filashift.com/filament)
- Project shopping passes material family, optional subtype, approximate RGB colour and the converted filament diameter (not nozzle diameter) into `/filament` in a separate tab. `pack=single` starts at lowest total price and requires `form=spool`, one unit and up to 1.25 kg; `pack=multi` keeps the 2 kg-and-up comparison by price/kg. Unknown packaging and refills never qualify as single spools. Test with `node scripts/check-single-spool.mjs`.
- SUNLU UpPromote uses the fixed placement names `filashift-finder` and `filashift-converter` in `sca_source`. Compare these in partner reports; neither contains visitor or project data. A working link is not proof of a credited sale.
- Flashforge one-spool fallback: require a single unambiguous 1kg product tag, spool and filament tags, color/type-only options, matching single-unit variant SKU and no pack text. Do not use shipping grams for net filament weight.
- Inventory schema 2: one offer per exact store variant URL. `ok: true` means that variant was available at refresh; `false` means sold out; `null` means unconfirmed. Never share colors, compare-at prices or stock between sibling variants. When deploying schema 2 for the first time, publish the verified feed before the web release.
- Regression checks: `python3 scripts/test_filament_variants.py`; `node scripts/check-filament-partners.mjs` checks the live finder at mobile and desktop widths. Amazon is a tagged search link, not store inventory.
- Page: `client/src/pages/filament.tsx` (route `/filament`; filashift.com uses real paths, other hosts use `#/` routing, see `client/src/routing.ts`). Shared header/footer in `client/src/components/site-chrome.tsx`.

Reads each brand store's public Shopify `products.json` and writes `/var/www/filashift-data/filament.json`. It refuses to overwrite the file when fewer than 50 offers parse, so a bad run leaves the last good data in place.
- Schedule: `deploy/filashift-filament.service` + `.timer` in `/etc/systemd/system/`, runs at 00/06/12/18:15 UTC (+ up to 10 min random) as user caddy. Manual run: `systemctl start filashift-filament.service`; logs: `journalctl -u filashift-filament`.

- An optional `amazonTag` in the publicly served `config.json` enables the tagged Amazon search box. Use only public referral settings there, never account credentials.
- Stores (edit `STORES` in the script): us.polymaker.com, us.elegoo.com, eryone3d.com, www.overture3d.com, atomicfilament.com, www.inslogic3d.com, www.jayo3d.com, www.amolen.com, www.protopasta.com, kingroon.com, www.printedsolid.com (reseller, brand = vendor), store.sunlu.com, siraya.tech, www.sovol3d.com, qidi3d.com, us.anycubic3d.com, www.flashforge.com, us.snapmaker.com, www.3dfuel.com (added Nov 23 2026; not reachable: esun3dstore.com 403, Bambu US and Creality stores, MatterHackers). Test locally with `python3 scripts/collect_filament.py /tmp/out.json --cache /tmp/fil` and check counts per store before deploying a parser change.
- Affiliate links: add an `affiliates` map to config.json keyed by store host; no release needed. Two forms:
  - `{"store.sunlu.com": {"params": {"sca_ref": "12345.abcd"}}}` appends query parameters (UpPromote, Shopify `ref`, etc.).
  - `{"us.elegoo.com": {"template": "https://elegoo.sjv.io/c/XXX/YYY/ZZZ?u={url}"}}` wraps the product URL for networks such as Impact or Awin (`{url}` is URL-encoded).
  Links that get an affiliate are marked `rel="sponsored"` and the disclosure appears on the prices page and in the converter's "Filament for this print" panel. Keep `amazonTag` alongside. Validate JSON with `python3 -m json.tool` before saving.
- "Filament for this print" (converter result): per used slot, the two cheapest in-stock 1.75 mm single spools (0.5–1.25 kg) whose colour is close to the project colour, one per store, plus links to `/filament?f=FAMILY&q=COLOUR` and a tagged Amazon search.
- "Find matching filament" (converter, per colour row, `shop-*-row-N-find`): opens `/filament` with `f` (family), `t` (finder type label such as `PLA Silk`, `PLA Matte`, `PLA+`, `PETG High Speed`, `Nylon-CF/GF`; only when the designer's source presets agree on one, see `shopType`/`slotType` in `client/src/lib/shop.ts`), `d` (filament diameter), `color` (hex), `feeder` (`ams` for X1/X1 Carbon/X1E/P1S/P1P, `u1` for the Snapmaker U1, else omitted; `feederFor` in `reel-fit.ts`), `pack=single` and `sort=colour`. ΔE ≤ 5 very close, ≤ 12 close, ≤ 25 shown as "noticeably different", above 25 hidden. "No close colour match" appears when nothing is within 12 (or the colour alone hides every offer), with a "Show all colours" button.

With a colour, only close matches (ΔE ≤ 12) count. Return visits compare against the normal `/data/filament.json`; no other requests. Documented in the EN/ES privacy page next to the language/theme note.

## Problem reports (/api)

- Service: `filashift-api.service` runs `/opt/filashift/filashift-api.py` (stdlib Python, user caddy) on 127.0.0.1:8787; Caddy proxies `/api/*` with a 16 KB body cap. Source: `deploy/filashift-api.py`, unit `deploy/filashift-api.service`.
- Endpoints: `POST /api/report` (message, link, email, details, page; honeypot field `website`), `GET /api/health`.
- Printer requests use the same endpoint with `"kind": "printer-request"` and only brand, model, optional slicer, optional note (`message`) and page; stored reports carry `"kind": "printer-request"` (problem reports have no `kind`). Test: `python3 scripts/test-printer-request.py`. Limits: 5 reports per IP per hour, 200 per day overall. No request logging.
- Reports land in `/var/lib/filashift/reports/<id>.json` with `"status": "new"`. There is no outgoing email: the Ops Teammate checks daily (`ls /var/lib/filashift/reports`), triages, sets `status` to `seen`/`fixed`, and tells David about anything needing a reply (reply from support@jacksoncgc.com). Reports older than 12 months must be deleted (privacy page promise): `deploy/filashift-reports-cleanup.timer` does it daily once installed; otherwise run `find /var/lib/filashift/reports -name '*.json' -mtime +365 -delete`.
- The 3MF file is never sent; "conversion details" (file name, source/target, counts, warnings, browser) are included only if the visitor leaves the box ticked.
- Keep Caddy access logs disabled. The first-party page-view counter stores only UTC date and a sitewide total, outside the web root. No per-page breakdown, cookies, identifiers or event records. Counts begin at rollout; an absent row is not evidence of historical zero traffic. Offline, blocked, automated release-test, DNT and GPC views are not counted. Totals are approximate and not unique visitors.
- On the server run `python3 /opt/filashift/filashift-api.py --daily-views` for private CSV output (UTC date, views). The service has no public reporting endpoint. Preserve the SQLite file across releases.

## Tool changers (H3C, P3C, H2C, U1)

- `client/src/engine/tools.ts`: Bambu printers with `extruder_max_nozzle_count > 1` get a per-tool inventory (stock tools: H3C 9 incl. the 2.85 mm TPU PrintTool 8, P3C 5, H2C left + 4 rack hotends) written as `extruder_nozzle_count/_slot/_volume_type/_diameter`, `extruder_nozzle_stats`, and a filament → tool assignment (`filament_map`, `filament_nozzle_map` = physical slot id, `filament_volume_map`, `filament_extruder_variant`). H3C/P3C use `filament_map_mode = Nozzle Manual` (Bambu Studio keeps our tool assignment); H2C uses `Auto For Flush`, because Bambu Studio 2.9.2's CLI rejects Nozzle Manual on the two-extruder rack. Every plate in model_settings gets the same mode/maps; stale per-plate maps in slice_info.config are dropped.
- Only flexible 2.85 mm filament goes to a TPU285 tool (P3C: an optional 6th tool, with a warning); 2.85 mm flexible sources pick the `TPU-2.85` preset (build_profiles.py adds it for printers with a TPU285 variant). Rigid filament never lands on the TPU tool.
- Per-tool nozzle sizes: kept for Orca multi-extruder targets (U1, per-tool `nozzle_diameter`); Bambu targets get one diameter and a report warning (the Bambu CLI cannot slice multi-diameter projects without extra CLI presets). Multi-tool → single-nozzle keeps colours as AMS slots (info line).
- Test: build sources with a TPU 2.85 filament / 10 colours / mixed nozzles (patch project_settings), then `npx tsx scripts/matrix.ts /tmp/tc src.3mf:tag ... -- bambu-lab-h3c bambu-lab-p3c bambu-lab-h2c bambu-lab-x1-carbon snapmaker-u1`, slice with `scripts/slice-matrix.sh`, and check the G-code header (`filament_map_mode`, `filament_nozzle_map`, `extruder_nozzle_diameter`). Round trips: `scripts/roundtrip.ts src.3mf /tmp/rt bambu-lab-h3c snapmaker-u1 bambu-lab-x1-carbon`.
